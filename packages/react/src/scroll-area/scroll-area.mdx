# Scroll area

A bounded region with native scrolling and custom scrollbars, such as a long list inside a panel. Not for page scrolling or virtualized lists.

<Demo example="./examples/demo.tsx" />

## Usage

```tsx
import {ScrollArea} from '@earendil-works/elanor-react';

<ScrollArea.Root>
  <ScrollArea.Viewport role="region" aria-label="Release notes">
    <ScrollArea.Content />
  </ScrollArea.Viewport>
  <ScrollArea.Scrollbar>
    <ScrollArea.Thumb />
  </ScrollArea.Scrollbar>
</ScrollArea.Root>;
```

- **Root** needs a bounded height, set directly or by a flex or grid parent.
- **Viewport** is the element that scrolls. Name it, and put `ref`, `onScroll`, and scroll calls here. It's focusable only while content overflows, so keyboard users can scroll it.
- **Content** has padding by default, so scrollbars don't cover text or focus outlines. Add `style={{minWidth: 0}}` when content should shrink or truncate instead of growing wider.
- **Scrollbar** appears only when content overflows.

For right-to-left layouts, set `dir` on the element and `DirectionProvider` to the same direction.

## Visibility

By default the scrollbar shows whenever content overflows. With `visibility="scrolling"` on `ScrollArea.Scrollbar`, it shows only while the reader scrolls the area or points at the scrollbar, then fades out. Use it for a large area that is read more than scrolled, such as a conversation. Scrolling from code, new content and resizes don't show it. In forced colors it always shows. Only the React parts have `visibility`; `StaticScrollbar` always shows.

## Styling states

The thumb is `semantic.color.background.fill.primary.neutral` in every state, including while hovered and scrolling. Style the parts with these state attributes:

| Attribute                                      | Meaning                                                                       |
| ---------------------------------------------- | ----------------------------------------------------------------------------- |
| `data-has-overflow-x`, `data-has-overflow-y`   | Content is larger than the viewport                                           |
| `data-overflow-y-start`, `data-overflow-y-end` | More content above or below                                                   |
| `data-overflow-x-start`, `data-overflow-x-end` | More content at an inline edge                                                |
| `data-scrolling`                               | Scrolling is in progress                                                      |
| `data-hovering`                                | The pointer is over the area (Scrollbar)                                      |
| `data-visibility`                              | `always` or `scrolling` (Scrollbar, React only)                               |
| `data-reader-scrolling`                        | The reader is scrolling (Scrollbar with `visibility="scrolling"`, React only) |
| `data-orientation`                             | Scrollbar and Thumb axis                                                      |

`data-scrolling` is Base UI's guess at the reader scrolling and also marks some scrolls from code; `data-reader-scrolling` marks only the reader's own scrolling.

Don't wrap an element that already has `overflow: auto`. [Sidebar](/components/sidebar/) uses its own scrollbar visibility and overflow cues.

## Static rendering

On pages rendered on the server without React in the browser, use the static parts, and bind their behavior once the page has loaded. For both axes, add a horizontal `StaticScrollbar` and a `StaticCorner`.

```tsx
<ScrollArea.StaticRoot>
  <ScrollArea.StaticViewport role="region" aria-label="Release notes">
    <ScrollArea.StaticContent />
  </ScrollArea.StaticViewport>
  <ScrollArea.StaticScrollbar>
    <ScrollArea.StaticThumb />
  </ScrollArea.StaticScrollbar>
  <ScrollArea.StaticScrollbar orientation="horizontal">
    <ScrollArea.StaticThumb />
  </ScrollArea.StaticScrollbar>
  <ScrollArea.StaticCorner />
</ScrollArea.StaticRoot>
```

```ts
import {createScrollArea, enhance} from '@earendil-works/elanor-react';

enhance({'scroll-area': createScrollArea});
```

The behavior hides the native scrollbar and draws the custom one with the same states as the React parts. Without it, the viewport keeps its native scrollbar.
