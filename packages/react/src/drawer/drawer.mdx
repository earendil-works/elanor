Base UI Drawer supplies modal focus management, scroll locking and swipe dismissal.
Use `swipeDirection="left"` or `"right"` for side panels; the default is a bottom sheet.
Directions are physical, including in RTL.

<DrawerExample client:load />

```tsx
<Drawer.Root swipeDirection="left">
  <Drawer.Trigger render={<IconButton aria-label="Open navigation" />}>
    <MenuIcon />
  </Drawer.Trigger>
  <Drawer.Portal>
    <Drawer.Backdrop />
    <Drawer.Viewport>
      <Drawer.Popup>
        <Drawer.Content>
          <Drawer.Title>Navigation</Drawer.Title>
          <Drawer.Close render={<IconButton aria-label="Close navigation" />}>
            <CloseIcon />
          </Drawer.Close>
          <SideNavigation.Root>{/* Shared destinations */}</SideNavigation.Root>
        </Drawer.Content>
      </Drawer.Popup>
    </Drawer.Viewport>
  </Drawer.Portal>
</Drawer.Root>
```

Keep mobile `open` separate from [Sidebar](/components/sidebar/) `collapsed`.
The application owns breakpoints and routing: close the drawer when navigating or
returning to desktop, rather than CSS-hiding an open modal. `actionsRef.close()`
supports this without duplicating Drawer state. Controlled `open`, `onOpenChange`
and cancellable event details remain available.

Popup scrolls within the viewport. Compose Content to preserve mouse text selection;
use `data-base-ui-swipe-ignore` on controls that need their own gestures. Styling adds
no timed transitions; direct swipe movement follows the pointer.

The host owns overlay stacking through `Drawer.Portal` styling. With elevated headers,
give that portal `position: fixed`, `inset: 0` and `z-index: var(--semantic-number-layer-overlay)`.
Viewport bounds are required because the iOS backdrop is absolutely positioned.
Leave its backdrop, viewport and nested popups on their automatic layers.
