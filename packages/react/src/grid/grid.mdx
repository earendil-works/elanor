# Grid

Divides the available width into up to 12 equal tracks that respond to the grid's own width, not the viewport. Use it for card layouts and forms; wrap it in [Container](/components/container/) for a centered width cap.

<Demo example="./examples/demo.tsx" />

## Usage

```tsx
import {Card, Grid} from '@earendil-works/elanor-react';

<Grid.Root>
  <Grid.Item span={{base: 'full', small: 6, medium: 4}} render={<Card />}>
    Overview
  </Grid.Item>
  <Grid.Item>Full row</Grid.Item>
</Grid.Root>;
```

Items span a full row unless `span` says otherwise. `render` lets another component, such as Card, be the item without an extra wrapper.

## Breakpoints

`span` and `start` keys are container breakpoints. They query the nearest `Grid.Root`, including from inside a subgrid.

| Key      | Minimum grid width |
| -------- | ------------------ |
| `base`   | Always             |
| `xSmall` | 40rem              |
| `small`  | 48rem              |
| `medium` | 64rem              |
| `large`  | 80rem              |
| `xLarge` | 96rem              |

A capped Container leaves 76rem for content, so `large` and `xLarge` apply only when the cap is removed.

## Start

`start` places an item on a track, or with `end`, at the end of its row, such as a filter beside a heading. Key it by breakpoint like `span`. Below, the filter takes a full row in narrow grids and ends the heading's row from `xSmall` on, with no empty item to push it there.

<Demo example="./examples/start.tsx" />

`start` moves an item along its row, never before earlier items: one that can't start after the previous item begins a new row. Screen readers and keyboard focus follow the source order, so put items in the order they're read.

## Columns

Spans larger than `columns` are clamped to the column count, and starts move back until the item fits.

## Subgrid

Use `Grid.Subgrid` when one element, such as a list row or a card, must place its children on the parent's columns. Below, each project row is one element with its own background, and its cells line up with the header. Subgrid shares columns only; rows stay independent.

## Nested grids

A `Grid.Root` inside an item starts a new grid: it has its own column count and measures its own width.

## Placement rules

- Items and subgrids must be direct DOM children of their grid. Fragments are fine; wrapper elements are not.
- Other children use native CSS Grid placement, without the full-row default or clamping.
- Clamping reads `columns`, `span`, and `start`. If you set `grid-template-columns` or `grid-column` in CSS, handle all placement in CSS.
- Grid keeps source order. `start` changes where an item sits in its row, not the order it's read in.

## Changing breakpoints

Container queries can't use CSS variables, so `src/grid/grid.module.css` writes thresholds as values annotated with their tokens:

```css
@container elanor-grid (48rem /* token: semantic.dimension.breakpoint.small */ <= width) {
  /* Responsive rules */
}
```

After changing breakpoint tokens, update the annotated values in the Grid and Layout CSS:

```sh
pnpm --filter @earendil-works/elanor-react generate:css
```

`check` and `build` fail on stale values.
