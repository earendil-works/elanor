# Top navigation

The header bar of a site or app, with regions for identity, navigation, and actions. Arrange the regions with your own CSS; this page has recipes to start from.

<Demo example="./examples/demo.tsx" />

## Usage

```tsx
import {TopNavigation} from '@earendil-works/elanor-react';

<TopNavigation.Root>
  <TopNavigation.Identity />
  <TopNavigation.Navigation />
  <TopNavigation.Actions />
</TopNavigation.Root>;
```

Root renders a `header`; the regions render `div`s. Put links inside a `nav` with an `aria-label`, or use [Navigation menu](/components/navigation-menu/) for submenus. In a [Layout](/components/layout/), merge Root into the header with `<Layout.Header render={<TopNavigation.Root />}>`.

By default, the regions share one row, with free space between them, and wrap when space runs out. The navigation sits centered only when identity and actions have the same width; in the demo above, it is pushed left.

## Height

Root is `semantic.dimension.size.topNavigation` (64px) tall and centers its content, so the bar needs no block padding. With `box-sizing: border-box`, a bottom border you add counts toward the 64px. The height is fixed so that offsets below the bar can come from the same token: a sticky header and the page's scroll padding, so anchor jumps and focused elements stay clear of it. The token is in rem, so the bar grows with the user's font size.

Keep the bar to one row: on narrow screens, move links into a [Drawer](/components/drawer/) or a menu, as in [Responsive navigation](#responsive-navigation). Layouts that need more rows, like the stacked and centered recipes below, set `block-size: auto`; derive offsets for such headers from their measured height instead of the token.

```css
.header {
  position: sticky;
  inset-block-start: 0;
  z-index: var(--semantic-number-layer-sticky);
  border-block-end: var(--semantic-dimension-border-width-small) solid
    var(--semantic-color-border-secondary);
  background: var(--semantic-color-background-canvas);
}

html {
  scroll-padding-block-start: var(--semantic-dimension-size-top-navigation);
}
```

## Menu

For narrow screens, `Menu` collapses the navigation into a menu below the bar. `MenuTrigger` shows the menu icon, and the close icon while the menu is open; `MenuPopup` fills the window below `semantic.dimension.size.topNavigation`. It is built on Base UI's Dialog without modality: Escape, the trigger, and choosing a link close it, and the bar's other controls, such as a theme switcher, stay usable and leave it open.

<Demo example="./examples/menu.tsx" />

```tsx
<TopNavigation.Menu defaultPanel="main">
  <TopNavigation.MenuTrigger aria-label="Navigation menu" />
  <TopNavigation.MenuPopup aria-label="Navigation menu">
    <TopNavigation.MenuPanel panel="main">
      <TopNavigation.MenuList>
        <TopNavigation.MenuItem>
          <TopNavigation.MenuPanelTrigger panel="docs" />
        </TopNavigation.MenuItem>
      </TopNavigation.MenuList>
    </TopNavigation.MenuPanel>
    <TopNavigation.MenuPanel panel="docs" parent="main" backLabel="Main menu">
      <TopNavigation.MenuList>
        <TopNavigation.MenuItem>
          <TopNavigation.MenuCollapsible>
            <TopNavigation.MenuCollapsibleTrigger />
            <TopNavigation.MenuCollapsiblePanel>
              <TopNavigation.MenuList />
            </TopNavigation.MenuCollapsiblePanel>
          </TopNavigation.MenuCollapsible>
        </TopNavigation.MenuItem>
      </TopNavigation.MenuList>
    </TopNavigation.MenuPanel>
  </TopNavigation.MenuPopup>
</TopNavigation.Menu>
```

Panels hold the menu's levels. Each opening starts at `defaultPanel`; a `MenuPanelTrigger` slides to a nested panel, which starts with a back button and takes focus there. Panels slide with `semantic.transition.movement.disclosure`, instantly when the reader prefers reduced motion. One level of nesting. Within a panel, `MenuCollapsible` sections open in place, like [Side navigation](/components/side-navigation/)'s.

Items are styled for the menu on their own, not shared with Side navigation, and grow to 48px rows on touch screens. `active` marks the current page, or the panel trigger or section that contains it. Render the menu and the wide navigation from the same data, and switch between them with your CSS at your breakpoint.

## Responsive navigation

On desktop, destinations are in a [Sidebar](/components/sidebar/) and resources in the header. Below `semantic.dimension.breakpoint.medium`, both move into a [Drawer](/components/drawer/). They share the current selection; the sidebar's collapsed state stays separate from the drawer's open state.

The drawer closes when the window grows past the breakpoint, rather than being hidden by CSS. Try it: open the drawer on a narrow window, then widen it. The demo keeps selection in local state and opens the drawer inside its frame with Portal's `container`; an application uses its router and lets the drawer cover the viewport.
