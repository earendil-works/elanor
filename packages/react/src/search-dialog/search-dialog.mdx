# Search dialog

A modal search for a site or its docs: the field at the top, results as you type, key hints at the bottom. For filtering a list on the page, use [Search](/components/search/).

<Demo example="./examples/demo.tsx" />

## Usage

```tsx
import {SearchDialog} from '@earendil-works/elanor-react';

<SearchDialog.Root>
  <SearchDialog.Trigger>Search documentation</SearchDialog.Trigger>
  <SearchDialog.Popup aria-label="Search documentation" value={query} onValueChange={setQuery}>
    <SearchDialog.Form action="/search">
      <SearchDialog.Input name="q" />
      <SearchDialog.Close aria-label="Close search" />
    </SearchDialog.Form>
    <SearchDialog.Results>
      <SearchDialog.Status />
      <SearchDialog.Message />
      <SearchDialog.List aria-label="Results">
        <SearchDialog.Result href="/guides/deploying">
          <SearchDialog.ResultContext />
          <SearchDialog.ResultTitle />
          <SearchDialog.ResultExcerpt />
        </SearchDialog.Result>
      </SearchDialog.List>
    </SearchDialog.Results>
    <SearchDialog.Footer>
      <SearchDialog.Hint />
    </SearchDialog.Footer>
  </SearchDialog.Popup>
</SearchDialog.Root>;
```

The dialog doesn't search; find the results yourself and render them. Control the query with `value` and `onValueChange` on the Popup, render a `Result` per match, and show a `Message`, such as an [Empty state](/components/empty-state/), when there are none. `Status` announces the count to assistive technology. Clear the query when the dialog opens, in Root's `onOpenChange`, so each search starts empty.

The field is a combobox that controls the list. The first result is selected as results arrive; the arrow keys move the selection, and Enter or a click follows the selected result's link and closes the dialog. A click with a modifier key, such as opening the link in a new tab, leaves it open, and so does ⌘, Ctrl, or Alt with Enter, which opens the selected result in a new tab. Without results, Enter submits the form, so set `action` and the field's `name` for a search page.

Results are `a` elements. For a router's link component, pass it as `render`, such as `render={<Link />}`; it receives the Result's `href`.

The dialog sits `semantic.dimension.space.padding.xxxxLarge` from the top, so results grow downward without moving the field, and it is as wide as [Modal](/components/modal/). It grows with its results up to `semantic.dimension.size.maxHeight.searchDialog`, or the window if shorter. Only the results scroll, in a [Scroll area](/components/scroll-area/), so the scrollbar overlays them instead of narrowing them. The query uses `semantic.typography.ui.searchDialog.input`, one step above the UI text.

## Keyboard shortcut

The Trigger looks like a search field. The dialog binds no shortcut. To add one, create a handle with `SearchDialog.createHandle()`, pass it to Root, and call `open(null)` from a key listener. Show the keys in the Trigger with `shortcut`, such as a [Keyboard shortcut](/components/keyboard-shortcut/), and name them in `aria-keyshortcuts`. The shortcut and the Footer's hints show only on devices that hover, which usually have a keyboard.

## Static pages

On [static pages](/application-setup/#static-pages), use the static parts. `Form`, `Footer`, and `Hint` stay the same. The results come from a source you pass in your script instead of React, here a JSON list of `{url, context, title, excerpt}` objects at `/search-index.json`:

```tsx
<SearchDialog.StaticRoot>
  <SearchDialog.StaticTrigger>Search documentation</SearchDialog.StaticTrigger>
  <SearchDialog.StaticPopup aria-label="Search documentation">
    <SearchDialog.Form action="/search">
      <SearchDialog.StaticInput name="q" placeholder="Search documentation" />
      <SearchDialog.StaticClose aria-label="Close search" />
    </SearchDialog.Form>
    <SearchDialog.StaticResults>
      <SearchDialog.StaticStatus />
      <SearchDialog.StaticMessage state="idle">
        Search guides and reference pages.
      </SearchDialog.StaticMessage>
      <SearchDialog.StaticMessage state="empty">
        No results for "<SearchDialog.StaticQuery />
        ".
      </SearchDialog.StaticMessage>
      <SearchDialog.StaticList aria-label="Results" />
    </SearchDialog.StaticResults>
  </SearchDialog.StaticPopup>
</SearchDialog.StaticRoot>
```

```ts
import {
  createModal,
  createScrollArea,
  createSearchDialog,
  enhance,
  type SearchDialogStaticResult,
  type SearchDialogStaticSource,
} from '@earendil-works/elanor-react';

let pages: SearchDialogStaticResult[] = [];

const source: SearchDialogStaticSource = {
  async load() {
    const response = await fetch('/search-index.json');
    if (!response.ok) throw new Error(`The search index failed to load: ${response.status}`);
    pages = await response.json();
  },
  search(query) {
    const terms = query.toLowerCase();
    return pages.filter((page) => `${page.title} ${page.excerpt}`.toLowerCase().includes(terms));
  },
};

enhance({
  modal: createModal,
  'scroll-area': createScrollArea,
  'search-dialog': (element) => createSearchDialog(element, source),
});
```

The popup is a native modal dialog, opened and closed like [Modal](/components/modal/)'s static parts. Each opening starts with an empty query; the source loads when the dialog first opens, and up to ten results show once the query has two characters, the first selected. `StaticMessage`s show per state: `idle`, `short`, `loading`, `empty`, and `error`. The static dialog binds no shortcut either: from your key listener, open it by clicking its trigger, such as with `trigger.click()`, so it animates like any other opening. Give `StaticRoot` an `id` to open the dialog from other buttons too, with `commandfor` and `command="show-modal"`, and pass your own behavior names to `StaticPopup` in `data-elanor`.
