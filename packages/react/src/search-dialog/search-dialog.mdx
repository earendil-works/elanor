# Search dialog

A search that opens in a modal dialog, with the field at the top, results as you type, and key hints at the bottom. Use it for site or documentation search. For filtering a list on the page, use [Search](/components/search/).

<Demo example="./examples/demo.tsx" />

## Usage

```tsx
import {SearchDialog} from '@earendil-works/elanor-react';

<SearchDialog.Root>
  <SearchDialog.Trigger>Search documentation</SearchDialog.Trigger>
  <SearchDialog.Popup aria-label="Search documentation" value={query} onValueChange={setQuery}>
    <SearchDialog.Form action="/search">
      <SearchDialog.Input name="q" />
      <SearchDialog.Close aria-label="Close search" />
    </SearchDialog.Form>
    <SearchDialog.Results>
      <SearchDialog.Status />
      <SearchDialog.Message />
      <SearchDialog.List aria-label="Results">
        <SearchDialog.Result href="/guides/deploying">
          <SearchDialog.ResultContext />
          <SearchDialog.ResultTitle />
          <SearchDialog.ResultExcerpt />
        </SearchDialog.Result>
      </SearchDialog.List>
    </SearchDialog.Results>
    <SearchDialog.Footer>
      <SearchDialog.Hint />
    </SearchDialog.Footer>
  </SearchDialog.Popup>
</SearchDialog.Root>;
```

The application finds the results; the dialog shows them. Control the query with `value` and `onValueChange` on the Popup, render a `Result` per match, and show a `Message`, such as an [Empty state](/components/empty-state/), when there are none. `Status` announces the count to assistive technology. Clear the query when the dialog opens, in Root's `onOpenChange`, so each search starts empty.

The field is a combobox that controls the list. The first result is selected as results arrive; the arrow keys move the selection, and Enter or a click follows the selected result's link and closes the dialog. A click with a modifier key, such as opening the link in a new tab, leaves it open, and so does ⌘, Ctrl, or Alt with Enter, which opens the selected result in a new tab. Without results, Enter submits the form, so set `action` and the field's `name` for a search page.

Results are `a` elements. For a router's link component, pass it as `render`, such as `render={<Link />}`; it receives the Result's `href`.

The dialog sits `semantic.dimension.space.padding.xxxxLarge` from the top, so results grow downward without moving the field, and it is as wide as [Modal](/components/modal/). It grows with its results up to `semantic.dimension.size.maxHeight.searchDialog`, or the window if shorter. Only the results scroll, in a [Scroll area](/components/scroll-area/), so the scrollbar overlays them instead of narrowing them. The query uses `semantic.typography.ui.searchDialog.input`, one step above the UI text.

## Keyboard shortcut

The Trigger looks like a search field. The application chooses the keyboard shortcut that opens the dialog: create a handle with `SearchDialog.createHandle()`, pass it to Root, and call `open(null)` from a key listener. Show the keys in the Trigger with `shortcut`, such as a [Keyboard shortcut](/components/keyboard-shortcut/), and name them in `aria-keyshortcuts`. The shortcut and the Footer's hints show only on devices that hover, which usually have a keyboard.

## Static rendering

On pages rendered on the server without React in the browser, use the static parts. `Form`, `Footer`, and `Hint` stay the same. The results come from a source in the page's script instead of React:

```tsx
<SearchDialog.StaticRoot>
  <SearchDialog.StaticTrigger>Search documentation</SearchDialog.StaticTrigger>
  <SearchDialog.StaticPopup aria-label="Search documentation">
    <SearchDialog.Form action="/search">
      <SearchDialog.StaticInput name="q" placeholder="Search documentation" />
      <SearchDialog.StaticClose aria-label="Close search" />
    </SearchDialog.Form>
    <SearchDialog.StaticResults>
      <SearchDialog.StaticStatus />
      <SearchDialog.StaticMessage state="idle">
        Search guides and reference pages.
      </SearchDialog.StaticMessage>
      <SearchDialog.StaticMessage state="empty">
        No results for “<SearchDialog.StaticQuery />
        ”.
      </SearchDialog.StaticMessage>
      <SearchDialog.StaticList aria-label="Results" />
    </SearchDialog.StaticResults>
  </SearchDialog.StaticPopup>
</SearchDialog.StaticRoot>
```

```ts
import {
  createModal,
  createScrollArea,
  createSearchDialog,
  enhance,
} from '@earendil-works/elanor-react';

const source = {
  load: () => loadIndex(),
  search: (query) => index.search(query), // [{url, context, title, excerpt}, …]
};

enhance({
  modal: createModal,
  'scroll-area': createScrollArea,
  'search-dialog': (element) => createSearchDialog(element, source),
});
```

The popup is a native modal dialog, opened and closed like [Modal](/components/modal/)'s static parts. Each opening starts with an empty query; the source loads when the dialog first opens, and up to ten results show once the query has two characters, the first selected. `StaticMessage`s show per state: `idle`, `short`, `loading`, `empty`, and `error`. Keyboard shortcuts are the page's: open the dialog by clicking its trigger, such as with `trigger.click()`, so it animates like any other opening. Give `StaticRoot` an `id` to open the dialog from other buttons too, with `commandfor` and `command="show-modal"`, and pass the page's own behaviors to `StaticPopup` in `data-elanor`.
