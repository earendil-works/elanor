# Sidebar

A desktop sidebar that stays interactive when collapsed. For mobile, compose
[Drawer](/components/drawer/) with SideNavigation and keep drawer open state
separate from collapse. See the [responsive recipe](/components/top-navigation/#responsive-navigation).

## Composition

```tsx
import {Layout, Sidebar, SideNavigation, Stack} from '@earendil-works/elanor-react';
import {HomeIcon, SettingsIcon} from '@earendil-works/elanor-icons-react';

<Layout.Body>
  <Sidebar.Root render={<Layout.Aside aria-label="Application sidebar" />}>
    {({collapsed}) => (
      <>
        <Sidebar.Header>
          <Stack
            direction={collapsed ? 'column' : 'row'}
            gap={collapsed ? 'small' : 'auto'}
            align="center"
            style={{inlineSize: '100%'}}
          >
            <a href="/" aria-label="Acme workspace">
              {collapsed ? 'A' : 'Acme workspace'}
            </a>
            <Sidebar.Trigger />
          </Stack>
        </Sidebar.Header>
        <Sidebar.Content>
          <SideNavigation.Root aria-label="Application" variant={collapsed ? 'compact' : 'default'}>
            <SideNavigation.Group>
              <SideNavigation.GroupLabel>Workspace</SideNavigation.GroupLabel>
              <SideNavigation.List>
                <SideNavigation.Item>
                  <SideNavigation.Link href="/" active iconStart={<HomeIcon />}>
                    Home
                  </SideNavigation.Link>
                </SideNavigation.Item>
                <SideNavigation.Item>
                  <SideNavigation.Link href="/settings" iconStart={<SettingsIcon />}>
                    Settings
                  </SideNavigation.Link>
                </SideNavigation.Item>
              </SideNavigation.List>
            </SideNavigation.Group>
          </SideNavigation.Root>
        </Sidebar.Content>
        <Sidebar.Footer>
          <SideNavigation.Root aria-label="Account" variant={collapsed ? 'compact' : 'default'}>
            <SideNavigation.List>
              <SideNavigation.Item>
                <SideNavigation.Link href="/account" compactContent="AB">
                  Alex Brown
                </SideNavigation.Link>
              </SideNavigation.Item>
            </SideNavigation.List>
          </SideNavigation.Root>
        </Sidebar.Footer>
      </>
    )}
  </Sidebar.Root>
  <Layout.Main>{/* Main content, independently capped by Container */}</Layout.Main>
</Layout.Body>;
```

Root, Header, Content, and Footer default to `div`. Compose Root with
`Layout.Aside` for one aside landmark. Keep Trigger outside Content so it cannot
scroll out of reach.

Content uses Base UI Scroll Area. Its props, ref, and scroll events target the
**scrollable viewport**, not the sizing frame. Children sit in a measured inner
container, not directly in the viewport. Header and Footer remain stationary.

Root's children callback and each region's `render(props, state)` receive
`{collapsed: boolean}`. Render callbacks must spread props and forward refs.
These parts accept `className` and `style`, and expose `data-collapsed` when collapsed.

## State and toggle

```tsx
const [collapsed, setCollapsed] = useState(false);

<Sidebar.Root
  collapsed={collapsed}
  onCollapsedChange={(next, details) => {
    // Optional: details.cancel() vetoes the change.
    setCollapsed(next);
  }}
>
  {/* Compose regions as above. */}
</Sidebar.Root>;
```

Omit `collapsed` for local state; `defaultCollapsed` defaults to false. Do not
switch between controlled and uncontrolled modes. Persistence, routing, and
breakpoints belong to the application.

`onCollapsedChange(next, details)` provides Base UI Toggle's `event` and `cancel()`.
A controlled owner vetoing a change must also avoid updating its own state.

Trigger is a Base UI Toggle named “Collapse sidebar”; `aria-pressed=true` means
collapsed, not hidden navigation. Its `render`/`className`/`style` callbacks receive
`{pressed, disabled}`. It exposes `data-pressed` and `data-disabled`, not
`data-collapsed`. Override `aria-label` for localization, keeping it stable across
states; the tooltip is supplementary. Keep Trigger mounted and outside ToggleGroup.

## Explicit compact content

Set `SideNavigation.Root variant={collapsed ? 'compact' : 'default'}` explicitly.
Each Link needs `compactContent`, `iconStart`, or `iconEnd` (in that priority),
supplied in **both** states. Do not replace the navigation tree on collapse.

Compact content must be decorative, non-interactive, and fit the rail. String or
number labels supply `aria-label`; rich labels require an explicit nonempty
`aria-label`. Invalid compact links throw. Link elements, hrefs, refs, tab order,
and `aria-current` stay stable. Link and group labels remain in the accessibility
tree, visually hidden. Never put focusable descendants in hidden labels.

Base UI supplies hover/focus tooltips, Escape dismissal, and touch suppression.
Tooltip wrappers stay mounted; an internal provider shares the hover delay.

Provide compact branding, project switchers, and account controls yourself.
Keep named controls mounted and replace only decorative contents. Before
unmounting an expanded-only control, move focus to a persistent control.

## Sizing and scrolling

Widths are `semantic.dimension.size.sidebar` (210px) expanded
and `semantic.dimension.size.xLarge` (48px) collapsed, including the 4px divider.
Root owns insets; compact navigation targets are 32px high. Override sizes with CSS
or inline styles.

Content's vertical scrollbar appears while scrolling or dragging, not on hover.
A bottom fade and top line indicate remaining content. The fade does not intercept
clicks; keyboard focus replaces it with a line to keep links and outlines clear.
Forced-colors mode uses lines and keeps the scrollbar visible while overflowing.
Use standalone ScrollArea for other scrolling arrangements.

Root is capped at `100dvh`. Adjust `maxBlockSize` for sticky headers; the parent
layout controls stickiness. Keep fixed header/footer content small enough for
short viewports. Set `blockSize` to fill height even with short content.

Match initial collapse state on server and client. For RTL, match Base UI's
DirectionProvider to document direction. On narrow/touch layouts, keep destinations
and the toggle available; do not rely on tooltips to explain icons. Text-only docs
navigation should stay expanded, using SideNavigation without Sidebar.Trigger.
