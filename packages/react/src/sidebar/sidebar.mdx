# Desktop sidebar

A locally controlled desktop sidebar, not a mobile drawer or an application state
provider. It stays interactive when collapsed; it never hides the navigation.

These are hydrated React examples inside the existing Astro documentation preview.
They add no separate demo application or testing infrastructure. Use Tab to reach

“Focus Home and toggle from owner” focuses the link before changing state so its
retained DOM identity and focus can be inspected directly.

## Composition

```tsx
import {Layout, Sidebar, SideNavigation} from '@earendil-works/elanor-react';
import {HomeIcon, SettingsIcon} from '@earendil-works/elanor-icons-react';

<Layout.Body>
  <Sidebar.Root render={<Layout.Aside aria-label="Application sidebar" />}>
    {({collapsed}) => (
      <>
        <Sidebar.Header>
          <Sidebar.Trigger />
        </Sidebar.Header>
        <Sidebar.Content>
          <SideNavigation.Root
            aria-label="Application"
            variant={collapsed ? 'compact' : 'default'}
          >
            <SideNavigation.Group>
              <SideNavigation.GroupLabel>Workspace</SideNavigation.GroupLabel>
              <SideNavigation.List>
                <SideNavigation.Item>
                  <SideNavigation.Link href="/" active iconStart={<HomeIcon />}>
                    Home
                  </SideNavigation.Link>
                </SideNavigation.Item>
                <SideNavigation.Item>
                  <SideNavigation.Link href="/settings" iconStart={<SettingsIcon />}>
                    Settings
                  </SideNavigation.Link>
                </SideNavigation.Item>
              </SideNavigation.List>
            </SideNavigation.Group>
          </SideNavigation.Root>
        </Sidebar.Content>
        <Sidebar.Footer>
          <SideNavigation.Root
            aria-label="Account"
            variant={collapsed ? 'compact' : 'default'}
          >
            <SideNavigation.List>
              <SideNavigation.Item>
                <SideNavigation.Link href="/account" compactContent="AB">
                  Alex Brown
                </SideNavigation.Link>
              </SideNavigation.Item>
            </SideNavigation.List>
          </SideNavigation.Root>
        </Sidebar.Footer>
      </>
    )}
  </Sidebar.Root>
  <Layout.Main>{/* Main content, independently capped by Container */}</Layout.Main>
</Layout.Body>
```

The root defaults to a `div`. Compose it with `Layout.Aside` to get one aside,
rather than nested landmarks. Header, Content, and Footer are optional `div`
regions, not additional landmark elements. Put the persistent Trigger outside
Content so long navigation cannot scroll it out of reach.

Content uses a Base UI Scroll Area internally. Its `ref`, `render`, `className`,
`style`, native attributes, and scroll events target the **scrollable viewport**,
not its outer sizing frame. Content children sit in a measured inner container;
do not depend on them being direct DOM children of the viewport. The outer frame
fills the remaining sidebar height, leaving Header and Footer stationary.

Root's children callback and the `render(props, state)` callbacks on Root,
Header, Content, and Footer receive `{collapsed: boolean}`. The `render`
callback must spread its props and forward its ref. These parts expose
`data-collapsed` only while collapsed. Ordinary `className` and `style` props
are available.

## State and toggle

```tsx
const [collapsed, setCollapsed] = useState(false);

<Sidebar.Root
  collapsed={collapsed}
  onCollapsedChange={(next, details) => {
    // Optional: details.cancel() vetoes the change.
    setCollapsed(next);
  }}
>
  {/* Compose regions as above. */}
</Sidebar.Root>
```

Omit `collapsed` for local state; `defaultCollapsed` defaults to false.
Do not switch between controlled and uncontrolled modes. No storage, routing,
breakpoint detection, global shortcut, or public state provider is installed.

`onCollapsedChange(next, details)` retains Base UI Toggle's event details,
including `event` and `cancel()`. A controlled owner must also refrain from
updating its own state when vetoing a change.

Trigger is a Base UI Toggle with a default icon and stable accessible name
“Collapse sidebar”. `aria-pressed=true` means the collapse option is on.
It deliberately does not describe navigation as a hidden disclosure panel.
Its Base UI render/className/style callbacks receive `{pressed, disabled}`;
`data-pressed` and `data-disabled` expose its state. Trigger does not duplicate
`data-pressed` as `data-collapsed`; the other Sidebar parts retain `data-collapsed`.
Pass a localized stable `aria-label` to override the default; use the same label
in both states. Its tooltip supplements, rather than supplies, its name.
Keep Trigger mounted, and do not place it inside a ToggleGroup.

## Explicit compact content

Choose `SideNavigation.Root variant={collapsed ? 'compact' : 'default'}`
explicitly. Sidebar does not inspect children or automatically collapse arbitrary
content. Each compact Link requires `iconStart`, `iconEnd`, or `compactContent`
(in that priority after explicit compactContent). Supply these in **both** states.
Do not conditionally replace the entire navigation tree.

Compact content must be decorative, non-interactive, and fit the rail. A string
or number label becomes the independent `aria-label`; rich label children require
an explicit nonempty `aria-label`. Invalid compact links throw a descriptive error
rather than silently removing a destination. The original label remains mounted
and visually hidden. Link elements, hrefs, refs, tab order, and `aria-current`
remain stable across collapse. Group labels also remain in the accessibility tree.
Base UI handles hover/keyboard-focus hints, Escape dismissal, and touch suppression;
tooltip wrappers remain mounted even when hints are disabled in expanded mode.
One internal Tooltip.Provider groups the sidebar's hints: after the first hint
opens, nearby hints can appear immediately instead of repeating the hover delay.

Branding, project switchers, and account controls need consumer-owned compact
representations. Prefer one persistent named button/link and replace only its
decorative contents. If an expanded-only control must unmount, intentionally move
focus to a persistent control first. Never put focusable descendants inside
visually hidden label content.

## Sizing and scrolling

Expanded width is `semantic.dimension.size.sidebar` (approximately 210px);
collapsed width is `semantic.dimension.size.xLarge` (48px). Controls are 32px
and padding fits inside the rail. Override widths with normal CSS or inline styles,
not custom component variables. Root has a viewport-height cap; Content owns
one native scroll viewport with a custom vertical scrollbar. Header/Footer remain
outside that scroll area. The scrollbar appears only while scrolling or dragging,
not on hover, and hides again using Base UI's scrolling state. A bottom fade appears
only while more content remains below; it disappears at the end. A subtle top line
indicates content above. The fade cannot intercept clicks and is replaced by a
boundary line during keyboard focus so focused links and outlines stay clear.
In forced-colors mode, boundary lines replace the fade and the scrollbar stays
visible whenever content overflows. No extra public scrollbar configuration is added to Sidebar;
use standalone ScrollArea composition for a different scrolling arrangement.

When a sticky header reduces the available height, give Root a matching
`maxBlockSize` through normal styling (or the Layout.Aside render element's style).
Its default cap is `100dvh`. The parent layout controls sticky positioning.
For very short viewports, keep fixed header/footer contents small enough to fit.
Provide a definite `blockSize` if the sidebar should fill available height even
with short content.

There are no animations or application-owned layout measurements. Base UI handles
scrollbar geometry and overflow observation; CSS still controls sidebar sizing.
Set the same initial collapsed value on server and client. Base UI's DirectionProvider should match
the document direction for logical tooltip placement in RTL.

This is desktop navigation. On narrow/touch layouts, keep destinations visible
and offer the persistent toggle; do not rely on tooltips to explain unfamiliar
icons. Text-only docs navigation remains standalone SideNavigation without a
Sidebar.Trigger or compact variant.
