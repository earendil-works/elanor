# Layout

Page regions with document scrolling. All parts accept `render`, `ref`, `className`,
`style`, and native props. Routing and navigation state belong to the application.

| Part     | Default element | Responsibility                                             |
| -------- | --------------- | ---------------------------------------------------------- |
| `Root`   | `div`           | Isolated, unclipped page frame; document scrolling         |
| `Header` | `header`        | Optional top region; non-sticky by default                 |
| `Body`   | `div`           | Groups zero, one, or two asides with flexible main content |
| `Aside`  | `aside`         | Supporting region; sticky and scrollable on wide screens   |
| `Main`   | `main`          | Flexible main landmark, without a content-width cap        |
| `Footer` | `footer`        | Optional bottom region                                     |

Use one `Main` per document. When embedding a layout inside an existing main,
use `Layout.Main render={<div />}` instead. `Page` is a content group, not another
main landmark. A simple header/main/footer page needs no `Body`.

## Docs recipe

Navigation, Main, and TOC stay in source order when stacked; navigation remains
visible. The preview reduces Root's minimum height; omit that override in a page.

## App recipe

Keep sidebars **outside** the content Grid. Container centers content in the
remaining space, capped at `semantic.dimension.size.content.large` (1216px).

```tsx
import {Container, Layout, Page, SideNavigation, Stack} from '@earendil-works/elanor-react';

<Layout.Root>
  <Layout.Body>
    <Layout.Aside
      aria-label="Workspace"
      style={{padding: 'var(--semantic-dimension-space-padding-medium)'}}
    >
      <Stack>
        <a href="/">Workspace</a>
        <SideNavigation.Root aria-label="Application">
          <SideNavigation.List>
            <SideNavigation.Item>
              <SideNavigation.Link href="/projects" active>
                Projects
              </SideNavigation.Link>
            </SideNavigation.Item>
            <SideNavigation.Item>
              <SideNavigation.Link href="/settings">Settings</SideNavigation.Link>
            </SideNavigation.Item>
          </SideNavigation.List>
        </SideNavigation.Root>
        <a href="/account">Account</a>
      </Stack>
    </Layout.Aside>
    <Layout.Main>
      <Container>
        <Page>
          <h1>Projects</h1>
          {/* A Grid may go here; it fills this Container independently. */}
        </Page>
      </Container>
    </Layout.Main>
  </Layout.Body>
</Layout.Root>;
```

To use another component as the aside, pass `<Layout.Aside />` to its `render` prop
instead of wrapping it, e.g. `<Sidebar.Root render={<Layout.Aside aria-label="…" />}>`.
This avoids nested landmarks.

## Top navigation recipe

See [top navigation recipes](/components/top-navigation/) for inline, centered, stacked and responsive arrangements.

`render` combines TopNavigation and Layout.Header into one header landmark.
Without asides, omit Body.

```tsx
import {Container, Layout, Link, Stack, TopNavigation} from '@earendil-works/elanor-react';

<Layout.Root>
  <Layout.Header
    render={<TopNavigation.Root />}
    style={{paddingBlock: 'var(--semantic-dimension-space-padding-xx-large)'}}
  >
    <Container>
      <Stack direction="row" align="center" gap="auto" wrap="wrap">
        <TopNavigation.Identity>
          <Link href="/">Elanor</Link>
        </TopNavigation.Identity>
        <TopNavigation.Navigation>
          <nav aria-label="Primary">
            <Link href="/about">About</Link>
          </nav>
        </TopNavigation.Navigation>
        <TopNavigation.Actions>
          <Link href="/login">Sign in</Link>
        </TopNavigation.Actions>
      </Stack>
    </Container>
  </Layout.Header>
  <Layout.Main>
    <Container render={<section aria-labelledby="intro" />}>
      <h1 id="intro">Build with Elanor</h1>
      <p>Your product content.</p>
    </Container>
    <Container width="full" render={<section aria-label="Showcase" />}>
      Full-width content retains gutters. Omit Container for a truly full-bleed region.
    </Container>
  </Layout.Main>
  <Layout.Footer>
    <Container>Your footer content</Container>
  </Layout.Footer>
</Layout.Root>;
```

## Sticky regions and narrow screens

At `semantic.dimension.breakpoint.medium` (64rem), Body becomes a row and Aside
becomes sticky at block-start, scrolling within `100dvh`. Below it, regions stack
in source order with normal-flow asides—not mobile overlays. For breakpoint edits,
see [Maintaining the CSS](/components/grid/#maintaining-the-css).

Avoid ancestor overflow or containment that changes the sticky scrollport.
Aside has no padding: leave room for focus indicators and keep scrollable content
keyboard-reachable, including noninteractive content. Composed components can
supply their own insets.

For a sticky header, set its height and adjust Aside's offset and available height:

```tsx
<Layout.Header className={styles.stickyHeader}>...</Layout.Header>
<Layout.Body>
  <Layout.Aside className={styles.belowHeader}>...</Layout.Aside>
  <Layout.Main>...</Layout.Main>
</Layout.Body>
```

```css
/* Application CSS Module. Enable the fixed-size recipe only on wide screens.
   Resolve this condition from semantic.dimension.breakpoint.medium in your build. */
@media (min-width: 64rem) {
  .stickyHeader {
    position: sticky;
    inset-block-start: 0;
    box-sizing: border-box;
    block-size: var(--semantic-dimension-size-x-large);
    z-index: var(--semantic-number-layer-overlay);
    background: var(--semantic-color-background-canvas);
  }

  .belowHeader {
    inset-block-start: var(--semantic-dimension-size-x-large);
    max-block-size: calc(100dvh - var(--semantic-dimension-size-x-large));
  }
}
```

This example uses a 48px header. Match both offsets to the actual height; leave
headers that wrap or grow in normal flow. Set `scroll-margin-block-start` on anchor
targets so the header does not obscure them.

To disable Aside stickiness, set `position: 'static'`, `maxBlockSize: 'none'`, and
`overflow: 'visible'` through `style`.
